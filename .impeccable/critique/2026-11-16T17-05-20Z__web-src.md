## 优先问题

### [P1] “界面动效”关不掉已经在跑的环境动效，首屏也没有常驻暂停

- **证据**：动效开关关掉后 8.2 秒，首屏计数从 `04 / 06` 走到 `05 / 06`，光尘 canvas 的数据 URL 仍在变化；`restartTimer()` 只在启动时读 `motionAllowed()`，`HeroDust.start()` 只在挂载时读。开关本身没有变成响应式状态。
- **为什么重要**：这是用户主动选择的“减少动效”，却只关掉了 CSS 过渡；对前庭敏感的人是信任问题，也触到 WCAG 2.2.2（自动播放超过 5 秒的动效需要暂停/停止/隐藏）。首屏轮播只有 hover/focus 暂停，没有可见的暂停控制。
- **修法**：把动效偏好做成响应式（`useMotionPreference` 或共享 reactive 状态）；`HomeView`/`HeroDust` watch 它，清 interval、cancel rAF、停 settle；首屏加一个 44px 的暂停/播放按钮；用 IntersectionObserver 在离屏时停光尘和轮播；保留系统 `prefers-reduced-motion` 的动态监听。
- **位置**：`web/src/views/HomeView.vue:137-143,215`；`web/src/components/HeroDust.vue:83-98`；`web/src/composables/useMotion.ts`。
- **建议命令**：`/impeccable animate`

### [P2] 文章页：快门失效 + 目录溢出

- **快门失效**：`PostView` 的根是 `Teleport` + `div.shell`，是 fragment；`App.vue` 的 `<Transition name="shutter">` 无法动画 fragment。浏览器控制台稳定报：`[Vue warn]: Component inside <Transition> renders non-element root node that cannot be animated`。结果：首页/图库有 180ms 收起 + 320ms 展开，文章页没有。
- **目录溢出**：1440×900 下桌面目录高 1107px（视口 900），`overflow: visible` 且 `position: sticky`；最后几节在视口外不可见/不可达。390 下 `<details>` 展开高 1004px，点完某一节后仍保持展开（`open=true`，scrollY 1864），且 summary 没有可见的展开标记。
- **为什么重要**：文章页是阅读主界面；动效不一致会让人觉得“卡了一下”，目录在长文里是导航而不是装饰。
- **修法**：把 Teleport 放进单一根元素（或把阅读进度条提升到 App），让 Transition 能接管；`.toc` 加 `max-height: calc(100dvh - 112px); overflow-y:auto; overscroll-behavior:contain`，并在 active 变化时 `scrollIntoView({block:'nearest'})`；移动端 details 选择后关闭、summary 加 chevron。
- **位置**：`web/src/App.vue:17-21`；`web/src/views/PostView.vue:1,148`；`web/src/styles/article-page.css`（`.toc`）。
- **建议命令**：`/impeccable adapt`

### [P2] 图作被固定框裁切

- **证据**：图库每格 4:3 `object-fit:cover`，1440 下格子 321×241；竖图 No.002（缩略图 376×640，原图 1203×2048）被裁成 321×241；切到“竖构图”仍是同样的裁切。说说里一张 2200×4508 的 B50 截图在 390 下渲染成 115×115，几乎无法辨认。
- **为什么重要**：站点的主张是“收藏图是主角”；把竖图和长截图裁成便于排版的方块，正好取消了主角的信息。这是最影响“图库第一眼”的问题。
- **修法**：按每张图的宽高比排（CSS columns/瀑布流或变高单元），或对竖图/长截图用 `contain` + 纸色/墨色留白；说说的截图给更高的缩略图（如 4:5 或 intrinsic ratio），别固定 1:1。编号与真实尺寸的元数据条保留。
- **位置**：`web/src/styles/stills.css`（`.stills-grid__img` / `ArtPlate ratio`）；`web/src/styles/pages.css`（`.logrow__images .arc-plateimg { aspect-ratio:1 }`）。
- **建议命令**：`/impeccable layout`

### [P2] 微字号：40 条 8.5–11px，字距 0.22–0.28em

- **证据**：overlay 40 条 undersized；实测品牌副标/导航英文 8.5px、统计标签 9px、眉标 10–10.5px、图版元数据 9.5–10.5px、标签计数 10.5px、菜单编号 11px。英文标签字距 0.22–0.28em（设计语言建议 0.14–0.18em）。
- **为什么重要**：这些不是纯装饰——记录编号、标签计数、图版尺寸是内容；在 1440 和 390 都偏难读，和“数字要能读”的档案感相反。
- **修法**：把信息型微标签的下限提到 11–12px（记录 No.、标签计数、图版尺寸、菜单编号、统计标签）；8.5–9px 只留给与中文重复的英文副标；字距收回到 0.14–0.18em；保留展示页大字标的 0.0x 负字距。
- **位置**：`web/src/styles/components.css`（brand/nav/footer/tag count）；`web/src/styles/hero.css`（stat label/plate）；`web/src/styles/pages.css`（record no/plate meta）。
- **建议命令**：`/impeccable typeset`

### [P2] 强调色令牌漂移

- **证据**：把强调色设为 `#5fe3cf` 后，顶部当前项背景是 `rgb(95,227,207)`，但首屏 `//`、当前 tick、按钮 hover、外观面板选中主题、查看器按钮 hover 仍是 `rgb(255,111,165)`。`hero.css`/`viewer.css`/`appearance.css` 共二十余处硬编码粉色。
- **为什么重要**：强调色是“当前/可点击/需要看一眼”的唯一信号；只改一半会让两套语义同时存在，也让自选强调色这个功能变得不可信。
- **修法**：这三处固定深色表面改用 `rgb(var(--c-accent))` / `var(--c-accent-ink)`；预设色板本身保留字面值；把“命令面”固定深色作为有意的例外写进 token 注释，而不是把粉色写死。
- **位置**：`web/src/styles/hero.css:77,182,221`；`web/src/styles/viewer.css:93,120,138`；`web/src/styles/appearance.css:44,97,130,166,201,229`。
- **建议命令**：`/impeccable polish`
